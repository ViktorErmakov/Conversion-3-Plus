## Запросы

Оба контура, XDTO и XML. Вкладка «Запросы» в `НастройкаПравилОбмена` открывает элемент `Справочник.Запросы`. Поле `ТекстЗапроса` — текстовый документ. Справочник в расширении заимствован, формы элемента нет, консоли нет.

- Консоль на `ТекстЗапроса`. Режим `setLanguageMode('bsl_query')`, подсказки полей из метаданных релиза — тот же приём, что в пункте «Редактор запроса». Платформенный конструктор остаётся закрытым [#28](https://github.com/ViktorErmakov/Conversion-3-Plus/issues/28).
- Параметров обработчика у этой формы нет. Макет `ПараметрыОбработчиков` текст запроса не описывает, в `customObjects` список страницы не кладём.
- Глобальный поиск уже читает `ТекстЗапроса` и открывает `Справочник.Запросы.Форма.ФормаЭлемента`. Форма не слушает `Расш1_ПереходКВхождению`, хоста консоли нет, фраза не выделяется. После консоли — тот же переход, что у алгоритмов: оповещение, `revealLineInCenter` и `setSelection` на строке вхождения.

## ПКПД и ПКС

Контур XML. У каждой новой консоли имена параметров берутся из макета `ВыгрузкаОбработчиковXML.ПараметрыОбработчиков`, область на событие, целиком, вместе с `ФайлОбмена`. Список кладётся в `customObjects` через `ОписаниеПараметровСтраницыJSON`. Описание объекта релиза — у `Источник` и `Объект`, остальные имена с пустым описанием. Подсказка формы шире макета, в подсказку кода её не копировать. `Расш1_ИменаПараметровПКО` с областями `ПКО_*` не совпадает, для ПКПД его не копировать.

`ФормаЭлементаXDTO` предопределённых данных — сопоставление значений, полей кода нет, консоль туда не ставить.

Справочники в расширении заимствованы, модулей форм нет.

## Паритет консоли

У каждого пункта: что видит разработчик правил, зачем это при обмене, какой вызов консоли, у кого из трёх это есть.

- Контекст обработчика. В подсказке параметры страницы, алгоритмы, запросы и параметры конвертации, чтобы не помнить сигнатуру и не искать имя по справочнику. Тот же JSON, что уже кормит `customObjects`, плюс `updateCustomFunctions` и `setCustomSignatures`. Типы локальных переменных редактор выводит сам. Параметры страницы XML ПКО уже отдаются, этого мало. Есть у бустера.
- Редактор запроса. Поле текста запроса переключается `setLanguageMode('bsl_query')`, подсказки полей берутся из уже загруженных метаданных релиза. Это не конструктор из #28: `EVENT_QUERY_CONSTRUCT` есть, но платформенный конструктор видит только базу КД. Есть у бустера.
- Переход к определению алгоритма и запроса. `setOption('generateDefinitionEvent', true)`, по `EVENT_GET_DEFINITION` открывается элемент справочника. Внутри текущего текста остаются `revealDefinition` и `goToFuncDefinition`. Есть у бустера.
- Закладки строк на время открытой формы: `addBookmark`, `getBookmarks`, `goNextBookmark`, `goPreviousBookmark`. Команды на нашей панели, контекстное меню редактора не дописываем. Есть у бустера.
- Подсветка правок с момента открытия: `setOriginalText` кладёт исходный текст, редактор рисует виджет изменений. Режим `compare` для двух произвольных текстов не используем. Есть у бустера.
- Английские подписи параметров обработчика, когда `ЯзыкПодсказок = en`. Наши строки в том же JSON подсказок. Переключение встроенного языка редактора уже делает `switchLang`. Есть у бустера.
- Свойства `ОбъектXDTO`, контур XDTO. Свойства пакета формата кладутся в `customObjects` параметра обработчика. `setObjectContext` не подходит: он подставляет реквизиты только у `ЭтотОбъект`. Есть у бустера.
- Выбор релиза подсказки, если у конвертации их несколько. Реквизит формы и тот же `EVENT_GET_METADATA`. По умолчанию XDTO — `Конфигурация`, XML — сторона обработчика. Есть у TipsInCD3.
- Страница единственного заполненного обработчика. Пустые обработчики не активировать. Если заполнен один — открыть его страницу. Логика формы, к консоли не обращается. Есть у бустера.

Методы общих модулей, объекта и менеджера берутся из `Расш1_ТекстыМодулей`. Отдельная задача появится только если по факту не всплывают методы менеджера или объекта: тогда добрать их в тот же регистр, без разбора исходников на лету.

## Не делаем

Без правки HTML/JS редактора этого нет, в работу не ставим:

- Два метода, которые TipsInCD3 вшивает в `bsl_console`.
- Свой разбор типов локальных переменных сверх того, что редактор уже делает по `Новый`, присваиванию и результату метода.
- F12 внутрь текста чужого модуля. `parseMetadataModule` даёт список экспортных методов в подсказке. `goToFuncDefinition` ищет процедуру только в текущем тексте. `EVENT_GET_DEFINITION` сообщает имя, место в чужом модуле редактор не принимает.
