## Что уже сделано

Общее для обоих контуров:

- HTML-макет `bsl_console` одним файлом, без zip / `file://`
- Один хост `Расш1_КонсольHTML` и реестр `Расш1_РеестрАлгоритмов`
- Форма `Расш1_НастройкиКонсолиКода`: тема (`Расш1_ТемыКонсолиКода`), насыщенность, шрифт, язык `ru`/`en`, флаг включения консоли (#17, #47)
- Запись текста с нормализацией перевода строк (#35)
- Скрипт `scripts/Update-BslConsole.ps1` (#30)
- Ленивые подсказки метаданных и тексты модулей `Расш1_ТекстыМодулей` (#33). Для XML направление выбирает релиз `Конфигурация` или `КонфигурацияКорреспондент`

Покрытие форм:

| Форма | XDTO | XML |
|---|---|---|
| Конвертации | 4 обработчика, хост на `СтраницаОбработчики` | консоли нет, 15 полей на `ОбработчикиXML` |
| ПОД | 2 обработчика, хост на `ОбработчикиСобытийXDTO` | консоли нет, 4 поля на `СтраницыОбработчикиXML` |
| Алгоритмы | поле `Алгоритм` | то же поле, консоль создаётся только при `ЭтоКонвертацияXDTO` |
| ПКО | 4 обработчика, направление и `customObjects` | 8 консолей на `ОбработчикиXML` уже есть; в `ПослеФормированияКонсолей` направление обнуляется, `ПолучитьОписаниеПараметровJSON` для XML пустой |

Консоль на XML-форме создавать при включённом флаге и заполненной ссылке `Конвертация`. Саму `bsl_console` не менять. Перехват — `&После` или `&ИзменениеИКонтроль`.

Направление на XML фиксируется стороной обработчика: выгрузка — отправка, загрузка — получение. Свободный тумблер на этих страницах не нужен.

Параметры страницы (`customObjects`) брать из подсказки обработчика на форме, по той же схеме, что `КомпонентыОбмена` / `ДанныеИБ` у XDTO.

## Волна XML. Алгоритмы

Поле то же: `Элементы.Алгоритм`. Снять ограничение `ЭтоКонвертацияXDTO` при включённой консоли.

## Паритет консоли. После волны XML

Контур: общие `Расш1_*`, оба типа конвертации. Саму `bsl_console` не менять и не патчить, как это делает TipsInCD3. Зависимость от Infostart Toolkit не тащить.

На Инфостарте консоль кода встроена в КД 3 в двух публикациях:

| Публикация | Что даёт сверх подсветки |
|---|---|
| [Редактор кода, 1289837](https://infostart.ru/1c/tools/1289837/) | своя; подсказки метаданных, темы, замена вхождений. Конструктор запроса там в планах — это уже [#28](https://github.com/ViktorErmakov/Conversion-3-Plus/issues/28) |
| [Бустер КД 3, 1499859](https://infostart.ru/marketplace/1499859/) | детальный контекст обработчика, редактор запроса, глобальный поиск, закладки, переход к определению. Анонс: [Toolkit 2.1, 1533678](https://infostart.ru/journal/news/mir-1s/infostart-toolkit-2-1-avtokomplit-po-metodam-obshchikh-moduley-i-novye-vozmozhnosti-redaktora-monaco_1533678/) |

Третий редактор на той же консоли — [TipsInCD3](https://github.com/GenVP/TipsInCD3) (в списке продуктов `bsl_console`). Отдельной статьи на Инфостарте у него нет. Редакторы КД 2 ([1539336](https://infostart.ru/1c/tools/1539336/), [72813](https://infostart.ru/1c/tools/72813/)) в этот список не входят.

Уже совпадает с бустером и в задачи не ставится: подсветка, тема, шрифт, карта кода, номера строк, пробелы, строка состояния, сворачивание, перенос, язык подсказок `ru`/`en`, метаданные релиза, тексты модулей `Расш1_ТекстыМодулей`.

| Задача | Откуда | Что сделать |
|---|---|---|
| Контекст обработчика | Бустер: локальные переменные и типы, алгоритмы, запросы, параметры конвертации | В `customObjects` / подписи страницы отдавать параметры обработчика, алгоритмы и запросы этой конвертации, параметры конвертации. Типы — те, что консоль уже выводит через точку. Для XML это стыкуется с добивкой `ПолучитьОписаниеПараметровJSON` |
| Редактор запроса | Бустер: редактор на полях кода и запроса (ПКО, ПКС и т.д.) | Поля текста запроса открывать в `setLanguageMode('bsl_query')`, метаданные того же релиза. Конструктор запроса остаётся [#28](https://github.com/ViktorErmakov/Conversion-3-Plus/issues/28) |
| Глобальный поиск | Бустер | Поиск по текстам правил, алгоритмов и запросов выбранной конвертации, переход к месту, отбор по конвертации, поиск использований алгоритма и запроса из «Настройки правил обмена». В фоне |
| Переход к определению | Бустер, `F12` / `EVENT_GET_DEFINITION` | Из вызова алгоритма, запроса или метода модуля открывать элемент КД или позицию в тексте модуля. Внутри одного текста — штатные `revealDefinition` / `goToFuncDefinition` |
| Закладки редактора | Бустер | `addBookmark` / `getBookmarks` на время открытой формы. Это закладки строк редактора, не страницы формы |
| Подсветка правок | Бустер: «отображение изменений» | Если текущая сборка консоли умеет показывать правки относительно исходного текста (`compare` и соседние вызовы) — включить при открытии. Нет в API — задачу закрыть, консоль не патчить |
| Английский контекст обработчиков | Бустер, [issue #24](https://github.com/Evg-lylyk/DC3BoosterISToolkit/issues/24) | Имена и подписи параметров обработчика на `en`, когда язык подсказок `en`. `ЯзыкПодсказок` уже есть |
| Свойства `ОбъектXDTO` | Бустер, [issue #16](https://github.com/Evg-lylyk/DC3BoosterISToolkit/issues/16), контур XDTO | У переменной объекта XDTO подсказка свойств пакета формата той версии, что указана в конвертации |
| Выбор релиза подсказки | TipsInCD3 | Если у конвертации несколько релизов, на странице обработчика выбирать, чьи метаданные и модули подсказывать. Для XDTO по умолчанию остаётся `Конфигурация`, для XML — сторона обработчика |
| Вкладка с кодом | Бустер, [issue #7](https://github.com/Evg-lylyk/DC3BoosterISToolkit/issues/7) | Пустые обработчики не активировать. Если заполнен один — открыть его страницу |

Методы общих модулей, объекта и менеджера у бустера берутся из каталога выгрузки релиза. У нас источник — `Расш1_ТекстыМодулей`. Отдельная задача появится только если по факту не всплывают методы менеджера или объекта: тогда добрать их в тот же регистр, без разбора исходников на лету и без внешней компоненты.
